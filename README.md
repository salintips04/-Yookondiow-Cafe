# ระบบจัดการออเดอร์ร้านคาเฟ่

เว็บแอปสำหรับรับออเดอร์หน้าร้าน ออกใบเสร็จ และสรุปยอดขาย ใช้ได้ทั้งบนมือถือ แท็บเล็ต และคอมพิวเตอร์
ติดตั้งลงหน้าจอเป็นแอป (PWA) และขายแบบออฟไลน์ได้ ไม่ต้องมีเซิร์ฟเวอร์หรือฐานข้อมูล ข้อมูลทั้งหมดเก็บในเครื่องที่ใช้งาน

## ความสามารถ

- **สั่งซื้อ:** แตะเมนูเพื่อเพิ่มลงตะกร้า, เลือกท็อปปิ้ง, ปรับจำนวน, เลือกจ่ายเงินสดหรือโอน, คำนวณเงินทอน, ออกและพิมพ์ใบเสร็จ (มี QR พร้อมเพย์เมื่อจ่ายแบบโอน)
- **สินค้า:** เพิ่ม/แก้ไข/ลบสินค้า หมวดหมู่ และท็อปปิ้ง (ท็อปปิ้งผูกกับหมวดได้) พร้อมตรวจข้อมูลที่กรอก
- **สรุปยอด:** ยอดขายรายวัน แยกเงินสด/โอน, ยอดแยกตามสินค้า, ประวัติออเดอร์แบบแบ่งหน้า (มือถือ 5 รายการ, จอใหญ่ 10 รายการ), ดูใบเสร็จย้อนหลัง, ส่งออกยอดรายเดือนเป็นไฟล์ Excel (.csv)
- **ตั้งค่า:** ชื่อร้าน, โลโก้, QR พร้อมเพย์, ธีมสี, สำรองข้อมูล และคู่มือการใช้งานในแอป
- **สำรองข้อมูล 3 ชั้น:**
  - Google Drive ของร้าน: อัตโนมัติทุก 30 นาทีเมื่อมีการเปลี่ยนแปลง และทันทีเมื่อปิดหรือสลับออกจากแอป
  - สำเนาในเครื่อง: อัตโนมัติทุก 3 วัน และก่อนล้างข้อมูล นำเข้า หรือกู้คืน (เก็บเฉพาะชุดล่าสุดของแต่ละแบบ)
  - ไฟล์สำรอง `.json`: ดาวน์โหลดและนำเข้าเองได้
- **ใช้งานง่ายทุกอุปกรณ์:** มือถือมีแถบเมนูด้านล่างและหน้าต่างแบบเลื่อนขึ้นจากด้านล่าง จอใหญ่แสดงเมนูกับตะกร้าคู่กัน และใช้คีย์บอร์ดหรือโปรแกรมอ่านหน้าจอได้

## เปิดใช้งาน

แอปต้องเปิดผ่าน `http://` หรือ `https://` เท่านั้น
**อย่าเปิดไฟล์ `index.html` ด้วยการดับเบิลคลิก** เพราะเบราว์เซอร์จะไม่ให้บันทึกข้อมูล (แอปจะขึ้นกล่องสีแดงเตือน)

### ทดสอบในเครื่อง

ต้องมี Python 3 รันคำสั่งนี้ในโฟลเดอร์โปรเจกต์ แล้วเปิด <http://localhost:8934>

```bash
python -c "import http.server as h; h.SimpleHTTPRequestHandler.extensions_map.update({'.js': 'text/javascript', '.json': 'application/json'}); h.test(HandlerClass=h.SimpleHTTPRequestHandler, port=8934, bind='127.0.0.1')"
```

ไม่ใช้ `python -m http.server` ธรรมดา เพราะบน Windows จะส่งไฟล์ `.js` เป็น `text/plain` ทำให้ service worker ลงทะเบียนไม่ได้

### ใช้งานจริง

1. อัปโหลด 5 ไฟล์ที่มี ✅ ในตารางด้านบน ขึ้นโฮสต์ที่เป็น https เช่น Netlify, Cloudflare Pages หรือ GitHub Pages
2. เปิดลิงก์ในมือถือ แล้วติดตั้งเป็นแอป
   - **Android (Chrome):** เมนู ⋮ → "ติดตั้งแอป"
   - **iPhone (Safari):** ปุ่มแชร์ → "เพิ่มไปยังหน้าจอโฮม" (แนะนำให้ติดตั้งเสมอ เพราะ Safari อาจลบข้อมูลของเว็บที่ไม่ได้เปิดนาน 7 วัน)
3. ตั้งชื่อร้าน → เพิ่มสินค้า → เชื่อม Google Drive (หน้าตั้งค่า → สำรองข้อมูล มีขั้นตอนพร้อมปุ่มคัดลอกโค้ด)

## ข้อมูลเก็บที่ไหน

| ข้อมูล | ที่เก็บ |
|---|---|
| ออเดอร์ | IndexedDB (`cafe-order-data`) ถ้าเครื่องใช้ IndexedDB ไม่ได้ จะใช้ localStorage แทน |
| สินค้า, หมวดหมู่, ท็อปปิ้ง, ตั้งค่า, โลโก้, QR | localStorage (คีย์ขึ้นต้นด้วย `cafe_`) |
| สำเนาอัตโนมัติในเครื่อง | IndexedDB (`cafe-order-snapshots`) |
| สำรองบนคลาวด์ | Google Drive ของร้าน โฟลเดอร์ "สำรองข้อมูลร้านคาเฟ่" และแท็บ "ออเดอร์" ในสเปรดชีต |

- ข้อมูลแยกตามเครื่องและตามเบราว์เซอร์ ถ้าใช้หลายเครื่อง ให้ย้ายข้อมูลผ่าน Google Drive หรือไฟล์สำรอง
- แอปไม่ส่งข้อมูลไปที่อื่น นอกจาก Google Drive ของร้านเมื่อเชื่อมต่อไว้
- **อย่าแชร์ URL ของ Google Apps Script** เพราะใครมี URL จะอ่านและเขียนข้อมูลร้านได้
- พื้นที่: ออเดอร์ละประมาณ 0.3–0.5 KB ถ้าขายวันละ 100 ออเดอร์ จะใช้ประมาณ 15 MB ต่อปี

## การป้องกันข้อมูลเสีย

- **นำเข้าไฟล์ / กู้คืน / ดึงจาก Drive:** ตรวจทุกรายการก่อนใช้ ถ้ามีข้อมูลผิดรูปแบบจะไม่นำเข้าเลย และเก็บสำเนาข้อมูลเดิมไว้ก่อนเสมอ
- **ล้างข้อมูล / นำเข้า / กู้คืน:** ถ้าเก็บสำเนาไม่ได้ จะถามก่อน และเสนอให้ดาวน์โหลดไฟล์สำรอง
- **บันทึกออเดอร์ไม่สำเร็จ** (เช่น พื้นที่เต็ม): ไม่ออกใบเสร็จ และตะกร้ายังอยู่ครบ
- **เชื่อม Google Drive จากเครื่องใหม่:** ถ้า Drive มีข้อมูลอยู่แล้ว จะถามก่อนว่าจะดึงลงมาหรือเขียนทับ
- **สคริปต์บน Drive:** ถ้าข้อมูลที่ส่งขึ้นไปมีออเดอร์น้อยกว่าเดิม (เช่น หลังล้างข้อมูล) จะเก็บไฟล์เดิมไว้อีกชุด
- **ยอดเงิน:** ปัดเป็นสตางค์ทุกจุด และข้อความที่ผู้ใช้กรอกถูกกรองก่อนแสดงผล

## แก้ไขโค้ด

- โค้ดทั้งหมดอยู่ใน `index.html` ไฟล์เดียว: CSS ด้านบน, HTML, สคริปต์ Apps Script ใน `<script type="text/plain" id="cloudScriptSource">` และโค้ดหลักใน `<script>` ท้ายไฟล์ ไม่ต้อง build
- **ทุกครั้งที่แก้ไฟล์แอป ให้เพิ่มเลข `CACHE_NAME` ใน `service-worker.js`** (ตอนนี้คือ `cafe-order-v29`) เครื่องที่ติดตั้งแอปไว้จะได้เวอร์ชันใหม่
- ถ้าแก้วิธีใช้งานส่วนไหน ให้แก้คู่มือในแอปตามด้วย (popup `#guideModal` ใน `index.html`)
- ถ้าแก้สคริปต์ Apps Script ต้องนำโค้ดใหม่ไปวางใน Apps Script ของร้าน แล้ว Deploy เวอร์ชันใหม่ด้วย

## ปัญหาที่พบบ่อย

| อาการ | วิธีแก้ |
|---|---|
| กล่องสีแดง "หน้านี้บันทึกข้อมูลไม่ได้" | เปิดผ่านลิงก์ http/https หรือแอปที่ติดตั้ง ไม่ใช่เปิดไฟล์โดยตรง หรือออกจากโหมดไม่ระบุตัวตน |
| แถบสีเหลือง "ไม่ได้สำรองข้อมูล" | ขึ้นเมื่อไม่ได้สำรองเกิน 7 วัน กดสำรอง หรือกด × เพื่อปิดไว้ 3 วัน |
| อัปเดตแล้วยังเห็นเวอร์ชันเก่า | ปิดแล้วเปิดแอปใหม่ขณะต่ออินเทอร์เน็ต และตรวจว่าเพิ่มเลข `CACHE_NAME` แล้ว |
| เผลอล้างข้อมูลหรือนำเข้าผิดไฟล์ | ตั้งค่า → สำรองข้อมูล → สำเนาอัตโนมัติในเครื่อง → "กู้คืน" |
| ฟอนต์ไม่สวยตอนออฟไลน์ครั้งแรก | ฟอนต์ IBM Plex Sans Thai โหลดจาก Google Fonts ครั้งแรกต้องออนไลน์ หลังจากนั้นใช้ได้แม้ออฟไลน์ |

## สิ่งที่ยังไม่ได้ทดสอบกับของจริง

- การเชื่อมต่อ Google Drive ด้วยบัญชี Google จริง (ทดสอบด้วยตัวจำลองและรันสคริปต์กับ Drive/Sheets จำลองแล้ว)
- การติดตั้งเป็นแอปบน iPhone และ Android จริง (ทดสอบด้วยการจำลองขนาดจอ)
